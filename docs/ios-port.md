# Bringing Quiet Grid to iOS

Goal: ship Quiet Grid on the Apple App Store (iPhone and iPad) while the Android app on Google Play
and F-Droid keeps building and working from the same codebase.

## Decisions

| Topic | Decision |
| --- | --- |
| Approach | Kotlin Multiplatform (KMP) for shared code, Compose Multiplatform (CMP) for the UI. No SwiftUI rewrite: it would duplicate about 50k lines of UI, and every future game twice. |
| Module shape | A new `:shared` KMP library module holds the app code. `:app` stays as the thin Android shell (Activity, manifest, widgets, WorkManager). AGP 9 expects KMP code in a library module, not in the application module. |
| Build machines | No Mac or iPhone is needed. Every iOS build, link, simulator run, signing step and upload runs on GitHub-hosted macOS runners. |
| Xcode project | Generated on CI from an XcodeGen `project.yml`. No hand-edited `.xcodeproj`. |
| Signing | fastlane with an App Store Connect API key creates and fetches the certificate and provisioning profile on CI. Secrets live in GitHub Actions secrets. |
| Testing | Nobody tests on a real iPhone. QA is automated: simulator UI smoke tests, a CI screenshot gallery of every screen and game (iPhone and iPad, upright and sideways) as build artifacts, and crash-free run-throughs of every game. |
| Devices | iPhone and iPad. iPad reuses the Android tablet layouts. |
| Minimum iOS | iOS 18.0 (iPhone XS/XR and newer). The `macos-26` runners only ship iOS 26 simulators, so a separate `macos-15` job runs the same app on an iOS 18 simulator and the oldest supported version is tested. |
| Framework integration | The Xcode pre-build script runs `./gradlew -Pquietgrid.ios=true :shared:embedAndSignAppleFrameworkForXcode`, so one `xcodebuild` call builds the Kotlin code and the app. |
| Xcode version | CI uses `macos-26` runners (Xcode 26). App Store uploads need Xcode 26 or newer. |
| v1 scope | Every non-beta game, Journey, badges, mixes, stats, daily puzzles, and daily puzzle reminders (local notifications, Kotlin in `iosMain`, no Swift). Beta games are hidden on iOS. |
| Later | Home-screen widgets (WidgetKit, Swift). |
| Dependency injection | Plain constructor wiring replaces Hilt. Koin was rejected: a missing binding fails at runtime, and without a device runtime failures are found late. |
| F-Droid | iOS targets are opt-in through the Gradle property `quietgrid.ios=true`. Default builds declare JVM/Android targets only, so F-Droid's Linux build never downloads Kotlin/Native. |
| Android stays green | After every step: `./gradlew compileDebugKotlin assembleDebug testDebugUnitTest :engine:test :cli:test :shared:testAndroidHostTest` pass. |
| Privacy | The app has no INTERNET permission and collects nothing. App Store privacy label: "Data Not Collected". |

## Status

Done in order, skeleton first, so CI, XcodeGen and simulator problems show up before the large
refactor. Each step leaves the Android app building and passing its tests.

- [x] 1. **Puzzle engine on iOS.** `:engine` is a KMP module (`jvm`, plus `iosArm64` and
  `iosSimulatorArm64` with the flag). JVM-only calls were replaced with Kotlin stdlib equivalents;
  Unicode NFD decomposition for Theme Clear sits behind `expect`/`actual` (`java.text.Normalizer`
  on the JVM, `NSString.decomposedStringWithCanonicalMapping` on iOS). Engine tests live in
  `commonTest` on `kotlin.test` and run on the JVM and the iPhone simulator.
- [ ] 2. **iOS skeleton.** `:shared` with one small Compose screen (title plus a Sudoku solved by
  the engine) and `iosApp/` generated by XcodeGen. CI builds the app for the simulator, launches it
  and stores screenshots. Built; waiting for the first CI run.
- [ ] 3. **Strings and assets.** `strings.xml` (8 locales) and the puzzle banks move to Compose
  Multiplatform resources.
- [ ] 4. **Dependency injection.** Hilt replaced with plain constructor wiring.
- [ ] 5. **Storage.** DataStore Preferences and Room move to their KMP builds. Existing Android
  saves, settings, stats and history survive the change.
- [ ] 6. **Platform services.** `expect`/`actual` for haptics, keep screen awake, in-app language,
  daily reminders, storage file paths, and opening the theme-suggestion link.
- [ ] 7. **Screens move.** Games, navigation and the shell move into `:shared`, in slices.
- [ ] 8. **iOS polish and QA.** Safe areas, swipe-back, hidden beta games, simulator smoke tests,
  screenshot gallery for iPhone and iPad.
- [ ] 9. **Store.** Signing, TestFlight upload, App Store listing in 8 languages (reusing
  `fastlane/metadata`), privacy label, `PrivacyInfo.xcprivacy`, review submission.

## Building for iOS

iOS targets are only declared when the Gradle property `quietgrid.ios=true` is passed. Without it,
`:engine` builds for the JVM only, and no Kotlin/Native toolchain is downloaded.

- Compile the engine for iPhone: `./gradlew -Pquietgrid.ios=true :engine:compileKotlinIosArm64`
- Run the engine tests on the iPhone simulator (macOS only):
  `./gradlew -Pquietgrid.ios=true :engine:iosSimulatorArm64Test`
- Windows: compiling for iOS works (Kotlin builds Apple klibs on Windows), so iOS compile errors
  show up locally:
  `./gradlew '-Pquietgrid.ios=true' :engine:compileKotlinIosArm64 :engine:compileTestKotlinIosSimulatorArm64`.
  Quote the flag in PowerShell, which otherwise splits `-Pquietgrid.ios=true` at the dot. The first
  run downloads the Kotlin/Native toolchain (about 600 MB) into `%USERPROFILE%\.konan`. Linking and
  running the iOS tests need macOS, so CI does that.
- CI: the `ios-engine` job in `.github/workflows/ci.yml` (macOS runner) compiles the engine for
  iPhone and runs the engine tests on the simulator on every push and pull request to `main`.
- `:shared` is the Compose Multiplatform module the app code moves into. Its Android side always
  builds; its iOS side (framework `Shared`) only with the flag. Test its Android side with
  `./gradlew :shared:testAndroidHostTest` (`compileDebugKotlin` does not cover it). Compile its iOS
  side on Windows with `./gradlew '-Pquietgrid.ios=true' :shared:compileKotlinIosSimulatorArm64`.
- `iosApp/project.yml` is the XcodeGen spec of the iOS app (bundle ID `com.quietgrid.app`, iOS
  18.0, iPhone and iPad), with the SwiftUI host in `iosApp/iosApp/`. The `.xcodeproj` and
  `Info.plist` are generated on CI and never committed.
- CI: the `ios-app` job (`macos-26`) generates the project, builds the app for the simulator,
  launches it on an iPhone and an iPad on the newest iOS, fails if the app process is gone 15
  seconds later, and uploads the screenshots as the artifact `ios-skeleton-screenshots`. It also
  uploads the built app (`ios-simulator-app`) and runs the `:shared` tests on the simulator. The
  `ios-app-ios18` job (`macos-15`) installs that same app on an iOS 18 iPhone simulator, which is
  required, and uploads `ios-skeleton-screenshots-ios18`.

## Owner steps (Apple account)

Needed before step 9, not before:

1. In App Store Connect: accept the agreements, set EU trader status, create the app record with
   bundle ID `com.quietgrid.app`.
2. Create an App Store Connect API key (Users and Access > Integrations) and add it to GitHub
   Actions secrets.
3. Host `PRIVACY.md` at a public URL for the listing.
4. Fill in the App Privacy label ("Data Not Collected").
